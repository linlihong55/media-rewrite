# 手机悬浮文案助手产品需求说明书

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 手机悬浮文案助手（暂定） |
| 产品形态 | Android 自用应用 + Mac 本地处理服务 |
| 目标设备 | realme RMX3366 |
| 系统版本 | Android 14 / realme UI 5.0 正式版 |
| 文档版本 | V1.0 |
| 当前阶段 | 需求确认，尚未开始功能开发 |
| 使用范围 | 仅用户本人使用 |

## 2. 产品结论

第一版采用“手机负责操作，Mac 负责处理”的架构。手机通过悬浮窗接收用户手动粘贴的抖音或小红书视频链接，分别执行“提取文案”“改写文案”“保存”三个独立动作。Mac 继续使用电脑版本现有的视频解析、本地 Whisper 转写、改写模型、提示词、爆款特征库、PostgreSQL 和飞书多维表格写入逻辑。

手机与 Mac 通过 Tailscale 私有网络连接，不购买云服务器，不向公共互联网开放 Mac 端口。Mac 可以锁屏和熄屏，但必须保持开机、开盖、联网且不进入系统睡眠。

## 3. 产品目标

用户在手机上浏览抖音或小红书时，无需返回电脑，即可完成以下操作：

1. 复制当前视频分享链接。
2. 点击屏幕悬浮球并粘贴链接。
3. 提取视频口播文案。
4. 根据需要查看、编辑并改写文案。
5. 确认后保存到现有飞书多维表格。
6. 在手机端看到真实、可追踪的任务状态和保存结果。

## 4. 非目标

第一版不包含以下能力：

- 自动点击抖音或小红书分享菜单。
- 使用无障碍权限自动读取当前视频链接。
- Mac 关机、休眠或断网时继续处理。
- 云服务器部署。
- 多用户注册、成员管理、计费或公开分发。
- 直播、私密、付费、已删除或平台限制内容的解析保证。
- 小红书图文笔记、图片 OCR 和评论提取。
- 批量自动采集或无人值守抓取。

## 5. 用户使用流程

### 5.1 首次设置

1. 在 Mac 和手机安装 Tailscale，并登录同一用户的私有网络。
2. 在手机安装“手机悬浮文案助手”。
3. 授予“显示在其他应用上层”权限。
4. 按 realme UI 提示允许应用后台运行，并取消对该应用的省电限制。
5. 应用检测 Mac、处理服务、数据库、视频解析器、Whisper、改写模型和飞书连接状态。
6. 所有必需服务正常后，显示“电脑可用”。

### 5.2 日常使用

1. 用户在抖音或小红书中复制视频分享链接。
2. 用户点击悬浮球，打开操作面板。
3. 用户点击“粘贴”，应用从分享文案中识别第一个受支持的视频链接。
4. 用户点击“提取文案”。
5. Mac 下载临时视频、提取音频并使用本地 Whisper 转写。
6. 手机显示原文案，用户可查看和编辑。
7. 用户选择以下任一路径：
   - 直接点击“保存”，将视频信息和原文案写入飞书，改写稿留空。
   - 点击“改写文案”，查看或编辑改写稿后，再点击“保存”。
8. 手机显示保存是否成功以及飞书同步结果。

### 5.3 操作原则

- “提取文案”只提取，不改写、不保存。
- “改写文案”只改写，不保存。
- “保存”是唯一触发本地数据库和飞书写入的用户操作。
- 任何阶段都不得在用户未点击“保存”时写入飞书。
- 保存内容以手机编辑框中的当前内容为准。
- 用户修改原文案后再点击“改写文案”，应使用修改后的原文案作为模型输入。
- 用户重新提取时，应提示新结果会替换当前未保存的原文案和改写稿。
- 用户重新改写时，应提示新结果会替换当前未保存的改写稿。

## 7. 页面与交互说明

### 7.1 悬浮面板

悬浮面板从上到下包含：

1. 电脑连接状态。
2. 链接输入框和“粘贴”按钮。
3. 视频基本信息区：平台、标题、账号和封面（能获取时显示）。
4. “提取文案”按钮。
5. 原文案可编辑文本框。
6. “改写文案”按钮。
7. 改写稿可编辑文本框。
8. “保存”按钮。
9. 当前任务进度、错误和重试入口。
10. 草稿列表入口和设置入口。

长文案编辑时允许进入全屏编辑页，避免在小悬浮窗口内完成大量文字修改。

### 7.2 按钮状态

| 当前状态 | 提取文案 | 改写文案 | 保存 |
| --- | --- | --- | --- |
| 未粘贴有效链接 | 禁用 | 禁用 | 禁用 |
| 已粘贴有效链接 | 可用 | 禁用 | 禁用 |
| 正在提取 | 显示进度/可取消等待 | 禁用 | 禁用 |
| 提取完成 | 可重新提取 | 可用 | 可用 |
| 正在改写 | 可重新提取 | 显示进度 | 可保存原文案，但需提示改写仍在进行 |
| 改写完成 | 可重新提取 | 可重新改写 | 可用 |
| 正在保存 | 禁用 | 禁用 | 显示进度，防重复点击 |
| 保存完成后又编辑 | 可用 | 可用 | 显示“保存修改” |

## 8. 技术方案边界

### 8.1 手机端

- 使用 Android 原生 Kotlin 开发，以降低悬浮窗、前台通知和 realme UI 兼容成本。
- 使用系统悬浮窗权限显示入口。
- 使用本地数据库保存草稿和任务映射。
- 用户主动提交和查询任务；不在手机执行视频下载、Whisper 或模型推理。
- 长时间状态同步采用可恢复的后台任务机制，并显示必要的系统通知。
- 第一版以侧载 APK 方式自用，不发布应用商店。

### 8.2 Mac 端

- 复用现有 Next.js 处理服务、PostgreSQL、抖音/小红书解析器、ffmpeg、Whisper、改写 Skill 和飞书同步模块。
- 新增手机版专用的鉴权、任务、草稿同步和状态查询接口。
- 将当前同步长请求拆成可持久化的异步任务，避免手机断网导致流程结果丢失。
- 保存接口允许改写稿为空。
- 服务仅监听本机和 Tailscale 私有网络可达地址，不做路由器公网端口映射。
- 任务日志不得记录飞书令牌、模型密钥或完整认证凭证。

### 8.3 私有网络和鉴权

- Mac 与手机加入同一 Tailscale 私有网络。
- 只允许用户的手机设备访问 Mac 指定的处理端口。
- Tailscale 提供设备层访问控制；应用层仍使用独立随机令牌鉴权。
- 手机令牌存入 Android 安全存储，Mac 令牌存入服务端环境变量。
- 支持撤销旧令牌并重新配对。
- 不在 APK 中打包飞书凭证、模型密钥或数据库密码。

## 9. 数据规则

### 9.1 草稿数据

每条手机草稿至少包含：

- 本地草稿 ID。
- 服务端任务 ID。
- 平台。
- 原始分享文字。
- 归一化视频链接。
- 视频内容 ID。
- 标题、正文、标签和作者信息。
- 原文案及其最后编辑时间。
- 改写稿及其最后编辑时间。
- 提取、改写和保存状态。
- 本地记录 ID、飞书记录 ID和同步状态。
- 创建时间和更新时间。

### 9.2 去重规则

- 主去重键为“平台 + 视频内容 ID”。
- 短链接和标准链接解析为同一内容 ID 时视为同一视频。
- 每次提交动作带唯一请求编号。
- 重复保存时更新已有记录，不新增飞书行。

### 9.3 数据保留

- 视频和音频仅作临时处理，任务结束后删除。
- 原文案、改写稿和必要的视频元数据保存在本地数据库及用户确认后的飞书记录中。
- 未点击“保存”的草稿默认只保存在手机；服务端任务结果保留期限在开发前设为 7 天，可在实现阶段配置。

## 10. 安全与隐私要求

- 不开放公网端口，不使用路由器端口转发。
- 手机只能访问必要的处理接口，不能直接访问 PostgreSQL、文件系统或管理接口。
- 每个写操作验证身份和请求编号。
- 接口限制请求体大小、链接协议、支持域名、视频时长和同时处理数量。
- 拒绝本地文件路径、内网 URL 和非抖音/小红书来源，防止服务端请求伪造。
- 密钥只存放在 Mac，不通过任务结果返回手机。
- 错误信息对用户可理解，但不回传内部路径、命令参数、环境变量或完整第三方响应。
- 提供一键停止远程访问和撤销手机凭证的方法。

## 11. 性能与可靠性要求

| 指标 | 第一版目标 |
| --- | --- |
| 悬浮面板打开时间 | 正常情况下不超过 1 秒 |
| 提交任务反馈 | 网络正常时不超过 3 秒返回任务编号 |
| 状态恢复 | 手机重连后 10 秒内恢复最新状态 |
| 同时转写数 | 默认 1 个，其他任务排队，防止 Mac 资源过载 |
| 同时改写数 | 默认 1 个 |
| 单条视频时长上限 | 默认 20 分钟，可配置 |
| 任务超时 | 视频解析/下载、转写、改写分别设置独立超时 |
| 防重复 | 同一请求重试不产生重复任务或记录 |
| 临时文件 | 任务结束或失败后均清理 |

处理规模仍会影响等待时间和 Mac 的 CPU、内存、网络及模型调用量。第一版不限制用户每天手动提交的总条数，但通过单任务时长上限和单并发队列保护电脑。

## 12. 风险清单与应对

| 风险 | 影响 | 应对方案 | 第一版是否阻断 |
| --- | --- | --- | --- |
| Android 同时运行 Clash 与 Tailscale | 系统只允许一个 VPN，手机无法访问 Mac | 使用助手时停止 Clash并连接 Tailscale；切回 Clash 时重新授权 | 是，使用前必须切换 |
| 抖音游客 Cookie 被风控 | 分享链接解析返回 400 | 解析失败后自动使用 Mac Chrome 登录态和 yt-dlp 兜底；保持 Chrome 抖音登录有效 | 是，已实现兜底 |
| 抖音或小红书修改解析机制 | 视频无法解析或下载 | 错误分类、保留链接、支持重试，解析器独立维护 | 否 |
| 小红书分享链接缺少有效参数 | 解析失败 | 保留完整分享文本，提示重新复制分享链接 | 否 |
| Mac 睡眠、合盖、断网或停电 | 手机无法处理 | 明确离线状态；接电、开盖、禁止自动睡眠 | 是，使用条件 |
| realme 系统清理后台 | 悬浮球消失或状态更新延迟 | 悬浮前台服务、常驻通知、取消电池优化、实机测试 | 否 |
| 手机移动网络短暂中断 | 状态丢失或重复提交 | 异步任务、任务 ID、本地草稿、幂等请求 | 否 |
| 当前接口无鉴权且 CORS 全开放 | 未授权调用 | 手机版接口单独鉴权、限制 Tailscale 来源、收紧跨域策略 | 是，发布前必须解决 |
| 当前保存接口要求改写稿必填 | 无法只提取后保存 | 将改写稿改为可选，调整数据库及保存校验 | 是，功能必须修正 |
| 本地已保存但飞书同步失败 | 两处状态不一致 | 显示部分成功并支持单独重试飞书 | 否 |
| 重复提交或网络重试 | 重复飞书记录 | 内容 ID 去重、幂等请求、更新已有记录 | 是，发布前必须解决 |
| Claude CLI 登录或模型通道失效 | 改写失败 | 延用电脑版备用模型策略，显示实际失败原因 | 否 |
| Whisper 长视频耗时较长 | 等待过久、Mac 负载升高 | 最多3条并行、20分钟默认上限、进度状态；并行时接受更高CPU占用 | 否 |
| PostgreSQL 或 Docker 未启动 | 保存失败、任务状态不可持久化 | 健康检查、开机自启、手机显示具体故障 | 是，运行条件 |
| 飞书字段被删除、改名或权限过期 | 同步失败或字段错位 | 保存前检查目标表和字段，禁止静默写入其他表 | 否 |
| 自动学习吸收低质量内容 | 改写特征库被污染 | 与电脑版保持一致；后续可增加“是否学习”开关 | 否，已接受电脑版规则 |
| 手机或 Tailscale 设备丢失 | 未授权访问处理接口 | 撤销 Tailscale 设备和应用令牌 | 否 |

## 13. 验收标准

### 13.1 外网连接

1. 手机关闭 Wi-Fi，仅使用移动数据。
2. 手机能识别 Mac 在线并提交任务。
3. 未授权请求不能访问处理接口。
4. 手机断网 2 分钟后重连，可恢复原任务结果。
5. 同一请求重试不创建重复任务。
6. Tailscale 断开时显示“电脑离线”，不误报为解析失败。

### 13.2 悬浮窗

1. 悬浮球能在抖音和小红书界面显示、拖动、吸边和收起。
2. 点击悬浮球可完成粘贴、提取、改写和保存。
3. 提取后不会自动改写或保存。
4. 改写后不会自动保存。
5. 只提取后可以直接保存，飞书改写稿字段为空。
6. 原文案和改写稿均可编辑，保存当前编辑结果。
7. 清理最近任务、锁屏解锁和应用进程回收后，草稿可以恢复。
8. realme UI 进行一次系统内存清理后，悬浮服务能恢复或明确提示用户重新启动。

### 13.3 Mac 锁屏

1. Mac 接通电源、保持开盖并手动锁屏。
2. 手机使用移动数据提交一条约 3 分钟的视频。
3. 全程不解锁 Mac，完成提取、按需改写及保存。
4. 飞书记录的链接、原文案、改写稿和时间正确。
5. 锁屏 30 分钟后再次提交，仍能完成。
6. 连续处理 3 条视频，服务不退出，任务不丢失，临时文件被清理。
7. 让 Mac 进入真实睡眠时，手机显示电脑离线；Mac 唤醒后任务可重试或继续，不永久卡住。

### 13.4 业务全流程

| 用例 | 操作 | 预期结果 |
| --- | --- | --- |
| 抖音视频仅提取 | 提取文案 → 编辑 → 保存 | 原文案写入，改写稿为空 |
| 抖音视频改写 | 提取文案 → 编辑原文 → 改写文案 → 编辑改写稿 → 保存 | 当前原文和改写稿均正确写入 |
| 小红书视频仅提取 | 粘贴完整分享文本 → 提取文案 → 保存 | 正确识别链接并保存 |
| 重复视频 | 再次提取并保存 | 更新已有记录，不新增重复飞书行 |
| 飞书暂时不可达 | 点击保存 | 本地保存成功，明确提示飞书失败，可单独重试 |
| 手机断网 | 提交后断网再恢复 | 任务结果恢复，不重复处理或保存 |

每个用例必须同时核验手机状态、Mac 任务记录和飞书实际记录。只看到手机“成功”不算通过。

## 14. 开发前检查清单

以下信息不需要现在提供，可在开始实施和首次配对时现场确定：

- Tailscale 登录账号及 Mac、手机设备名称。
- 手机安装 APK 时是否需要通过数据线或无线调试。
- realme UI 实际显示的悬浮窗、电池优化和后台运行权限名称。
- 现有飞书目标表当前字段和权限的最终复核。
- 当前电脑版首选改写模型、备用模型和登录状态的运行验证。
- 选取 2 条抖音视频和 2 条小红书视频作为验收样本。

## 15. 实施顺序

1. 为 Mac 服务增加安全鉴权、健康检查和 Tailscale 访问限制。
2. 增加持久化异步任务、状态查询、幂等和断点恢复。
3. 调整保存逻辑，允许无改写稿保存并支持飞书单独重试。
4. 建立 Android 原生项目和安全配对流程。
5. 完成悬浮球、链接粘贴、三段式操作和草稿恢复。
6. 完成手机状态通知和错误提示。
7. 在局域网完成业务测试。
8. 使用移动数据完成外网连接测试。
9. 完成 realme UI 后台存活和 Mac 锁屏验收。
10. 输出自用 APK、安装说明、停止远程访问方法和故障排查说明。

## 16. 上线判定

满足以下条件后，第一版才可视为可用：

- 三个按钮严格独立，任何操作都不会未经确认自动保存。
- 仅提取后保存和提取改写后保存均通过真实飞书验收。
- 未授权设备无法调用手机接口。
- 手机移动数据、Mac 锁屏场景下完成完整流程。
- 断网、重复点击、飞书失败和服务重启不会造成重复记录或无提示的数据丢失。
- 所有模型、提示词、特征库和飞书字段行为与电脑版本一致。
